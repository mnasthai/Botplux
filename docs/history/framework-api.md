# Plux 公共插件 API 设计草案

状态：0.1 设计依据；首版 SDK 已实现。框架包为 `plux`，插件只依赖公开入口 `plux.api`。本文 Python 代码保留接口设计示意，实际名称、参数及当前限制以 [公共 SDK 源码](../src/plux/api/__init__.py) 和 [实现指南](implementation.md) 为准。

## 1. API 范围与依赖

Plux 负责原生通信、消息、数据、任务和运行管理；修仙及其他业务通过独立插件包接入。AI 与广播不进入本轮迁移。

- 实现层为 `data/messaging/runtime/adapters`；公开 API 定义模型与服务契约，不再经一个重复包装层。
- 插件使用公开模型和服务，不导入框架实现、C++ 编解码器或其他插件的内部模块。
- 框架服务提供通用原语，不包含 `Player`、`Battle`、法宝、奖励或经济规则。
- 插件拥有业务模型、规则校验、仓储、迁移和恢复决策；框架执行已声明的流程。
- 注册、依赖装配、调用、提交、任务调度和生命周期统一由 runtime 管理。
- 首版使用进程内可信本地插件、同步原子 handler 和后台 worker；插件隔离不构成安全沙箱。
- 公共 API、插件版本、配置格式、内容版本、状态版本和数据库迁移版本分别管理。

## 2. 公共消息与交付模型

公共数据对象不可变；时间采用带时区的 UTC 时间，持续时间使用明确单位。ID 是稳定、不透明的值，插件不解析其内部编码。

| 类型 | 必需信息与约束 |
| --- | --- |
| `BaseMessage` | `event_key`、账号、会话、发送者、观察时间、方向、内容质量；来源会话身份可查询 |
| `TextMessage` | 文本、提醒列表、可选引用；截断和读取失败有独立质量标记 |
| `ImageMessage` | `AssetRef` 或待解析媒体引用、可选尺寸；媒体未就绪可明确表达 |
| `VoiceMessage` | 媒体引用、可选时长及可选转写；转写与原始内容有明确来源 |
| `UnknownMessage` | 原始类型、受控原始记录引用、解析问题；保留事件身份，禁止伪装成空文本 |
| `ReplyIntent` | 稳定回复键、目标会话、文本或资产内容、提醒和引用、交付要求 |
| `AssetRef` | 资产 ID、版本、类型、内容校验信息；不承诺固定文件位置 |
| `ConnectionSnapshot` | 当前账号与原生会话、采样时间、来源、连接阶段、支持能力和可发送状态 |
| `Receipt` | 请求 ID、请求状态、发送尝试投影、关联证据、更新时间；执行与送达含义分开 |

```python
# 设计示意：具体字段类型、内容分型和构造器在实现前固定。
@dataclass(frozen=True)
class BaseMessage:
    event_key: EventKey
    identity: MessageIdentity
    observed_at: datetime
    quality: ContentQuality

@dataclass(frozen=True)
class TextMessage(BaseMessage):
    text: str
    mentions: tuple[MemberRef, ...] = ()
    quote: MessageRef | None = None
```

类型表达内容约束；摄取适配器负责一次性完成协议到公共模型的转换。公共模型不重复包装 JSONL 字段，也不丢弃不确定性。

`ReplyIntent` 表达希望产生的回复，插件不直接调用管道。事务执行器保存意图与 outbox，交付服务执行后提供 `Receipt`。

`accepted` 表示本地原生提交结果，不能证明收件人收到；`unknown` 表示执行结果不确定，不自动重发。连接支持某操作、完成握手和当前可发送是不同状态。

交付请求形成时持久保存请求 ID、账号/会话、目标、有效期、文本或 AssetRef 的版本/内容身份及逻辑内容指纹。原生提交准备阶段解析文件位置，在创建 attempt 前持久化完整 native payload 与协议指纹；此后路径、内容与协议指纹固定。逻辑资源位置可在准备前解析，资源版本不变；准备后重试与恢复不能换路径或内容。历史 outbox 迁移不得重算已固定指纹或修改已有尝试记录。

## 3. 调用上下文与长期服务

`PluginContext` 是公开的一次调用类型，只描述本次执行。插件不得保存它或将事务句柄传给另一个线程。

| 调用字段 | 含义 |
| --- | --- |
| `call_id`、`event_key` | 本次执行身份、稳定输入身份；任务调用使用稳定任务键 |
| `account`、`conversation`、`actor` | 调用身份；后台任务没有用户输入时显式为空 |
| `permissions`、`observed_at` | 已验证权限和输入观察时间 |
| `uow` | 有效事务作用域；无状态处理时为空，离开提交阶段后失效 |
| `cancellation` | runtime 的合作式取消信号 |

`PluginServices` 生命周期覆盖插件启用期间，由 runtime 按插件作用域注入。服务引用可以长期保留，调用中的事务不能长期保留。

```python
# 设计示意：类型化入口，不提供 get_service(name) 或任意内部对象查询。
class PluginServices(Protocol):
    messages: MessageServices
    data: DataServices
    tasks: TaskServices
    clock: Clock
    logger: PluginLogger
```

服务入口提供广度，具体用例通过构造参数接收所需的小接口。插件仓储工厂在装配时声明，runtime 在原子调用或任务提交阶段将它绑定到当前 UoW；仓储不自行连接或提交。

## 4. 插件声明、注册与生命周期

每个插件具有显式 manifest。首版使用配置中的 entrypoint 插件类清单加载，读取类级静态 manifest 后再构造实例；配置校验、资源与迁移声明无需先执行业务。插件模块导入只声明类型和元数据，不扫描目录、不使用 import 副作用注册、不提供热重载。

| Manifest 项 | 约束 |
| --- | --- |
| `plugin_id`、`version`、`api` | 唯一插件身份、插件版本和支持的公共 API 范围 |
| `dependencies`、`capabilities` | 显式插件依赖、所需平台能力；装配失败时报告具体缺失项 |
| `namespace`、`database_domain` | 数据归属和事务域；默认使用平台主数据库 |
| 配置、内容、状态与迁移声明 | 提供格式版本、加载/校验入口、迁移集和恢复入口 |

```python
# 设计示意：仅插件入口继承；内部规则、仓储和展示使用普通类或函数。
class Plugin(ABC):
    manifest: PluginManifest

    @abstractmethod
    def register(self, registry: PluginRegistry) -> None: ...

    def start(self) -> None: ...  # 默认无操作
    def stop(self) -> None: ...   # 默认无操作
```

构造与注册阶段只装配和声明，不调用服务执行业务读写。装配顺序为 manifest 与配置校验 → 轻量构造并注册 → 冲突检查 → 资源验证与迁移 → 恢复与 start → 开放调度；迁移、内容校验与资源检查成功后才能启动任务。生命周期内需要数据库操作时，由 runtime 创建专门调用作用域。

Registry 提供四类登记：命令、消息事件、定时计划、后台任务类型。登记项包含稳定 handler ID、输入类型/过滤条件、执行模式与顺序要求。

| 登记接口（设计示意） | 声明内容 |
| --- | --- |
| `command(CommandSpec)` | ID、触发词/解析器、`handler(input, context)`、执行模式和数据库域 |
| `event(EventSpec)` | ID、消息类型/过滤条件、handler、执行模式和串行键 |
| `schedule(ScheduleSpec)` | ID、计划、任务类型或回调、时区、遗漏时隙策略 |
| `task(TaskSpec)` | ID、输入/结果类型、阶段入口、并发键、重试与恢复策略 |

handler 返回 `Outcome`，包含 `success/rejected/noop`、稳定错误码、类型化结果、回复意图和任务意图。业务拒绝是正常结果；框架故障触发回滚和声明的故障策略。返回结果由 runtime 提交，插件不能自行确认消费完成。

- 命令默认只有一个匹配处理器；冲突在启动时失败，需要优先级时显式声明。
- 事件允许有意的多订阅，每个处理器拥有独立消费标记；顺序敏感业务声明串行范围。
- 定时计划只生成任务或调用；不允许插件自行启动无法监督的常驻线程。
- 后台任务声明执行与提交入口、并发键、超时、重试和恢复策略。
- `stop` 用于停止业务生产和释放资源；任务排空、超时及连接关闭由 runtime 协调。

修仙目标包为 `plux_plugins.xiuxian`，由其入口注册业务；框架内不保留修仙专用路由分支。

## 5. 消息服务

| 服务 | 公共能力 |
| --- | --- |
| 查询 | 按稳定身份查询消息、历史页、成员和会话资料；明确分页、缺失和资料时效 |
| 回复 | 校验并保存 `ReplyIntent`；返回请求引用，实际发送由 outbox worker 推进 |
| 交付 | 查询 `Receipt`、追加证据投影、订阅明确状态变化；未知状态不变成成功 |
| 媒体 | 解析入站媒体引用、准备出站资产、查询处理状态 |
| 连接 | 读取 `ConnectionSnapshot`，能力声明与当前状态分别可见 |

查询可使用独立只读作用域；需要和业务决策一致的查询参与当前事务。资料缺失、媒体未就绪和原生不可用使用明确结果，业务拒绝与服务故障分别表达。

| 典型调用（设计示意） | 语义 |
| --- | --- |
| `messages.history(query) -> Page[BaseMessage]` | 稳定游标分页，明确账号与会话范围 |
| `messages.member(ref) -> MemberSnapshot` | 显示资料时间和缺失字段，不推断权限 |
| `messages.receipt(request_id) -> Receipt` | 读取当前投影，历史尝试和证据仍可追溯 |
| `messages.connection() -> ConnectionSnapshot` | 只读快照，不取得原生客户端对象 |
| `messages.enqueue(intent, uow) -> RequestRef` | 仅在有效事务内使用；handler 通常通过返回 outcome 提交 |

插件可提交回复意图，不可控制原生尝试 ID、重绑原生会话或绕过交付队列。需要“提示提交后开始计时”的流程，由插件声明使用哪种 receipt 事件。

## 6. 数据服务

### 数据库、事务与迁移

首个实现使用 SQLite。驱动层管理连接、参数绑定、事务和能力；不同关系数据库还需要迁移及仓储 SQL 适配和契约验证。更换 driver 不保证任意数据库透明兼容。

数据库实例和插件 schema/namespace 单独登记。插件提供有序迁移集，迁移版本独立于插件版本；runtime 启动工作器前检查并执行。迁移失败保留版本状态并停止该依赖链。

迁移不得暗中删除其他插件数据；停用和卸载不自动删除 schema。清理业务数据需要单独、明确的维护操作。

```python
# 设计示意：仓储由插件实现，平台工厂负责当前事务绑定。
players = services.data.repository_factory(PlayerRepository)

def mine(command: MineCommand, call: PluginContext) -> Outcome:
    repo = players.bind(call.uow)
    result = mining.execute(repo, command, rules)
    return Outcome.success(result, replies=(render_reply(result),))
```

`call.uow` 的数据库域、线程/任务归属与有效期受检查。绑定仓储不开放跨域原子提交，也不提供任意全局 SQL 容器。

### 配置与内容目录

平台负责来源解析、格式解析、缓存、索引和版本发布；插件负责类型结构、范围、重复 ID、引用关系和业务机制校验。

内容通过 `CatalogRef(namespace, version)` 标识。加载形成不可变、类型明确的版本快照；业务调用读取内存对象，不逐条消息重读文件。

插件声明配置格式版本与内容版本；有效快照另有稳定内容摘要，能识别覆盖后实际生效的规则。新版本完整校验成功后一次发布，失败继续使用旧有效版本。

首版发布通过受控启动或重启完成，不承诺自动监视或插件热重载。内容版本发布能力保留独立接口，后续可以增加显式管理操作。

进行中的任务或活动声明所绑定版本。更新时选择继续旧版本、显式迁移或结束活动；禁止自动把旧状态套进新规则。仍被引用的版本需保留或可重建。

### 文件资产与可恢复快照

| 服务 | 操作与语义 |
| --- | --- |
| 资产 | 暂存、校验、发布、打开、增加/解除引用、声明保留策略；按插件 namespace 归属 |
| 暂存 | 未发布资源可识别、可过期；发布后得到不可变版本的 `AssetRef` |
| 快照 | 按稳定业务键保存、条件更新、读取、截止时间、结构版本及关联规则/资产引用 |
| 维护 | 分批检查失效引用、容量与滞留任务；制定回收、备份、恢复和重建流程 |

文件发布与数据库提交之间使用可恢复步骤：记录准备任务、发布完整资产、提交引用；中断后能够继续或回收。普通数据库回滚不能撤销已发布文件。

快照服务保证持久化与并发更新约束；状态转换、过期结算和恢复动作由插件决定。副本可以持久恢复，不要求沿用旧 TEMP 表。

回收依据引用、任务状态和保留策略。未完成发送仍引用的资产不得只因文件年龄删除。备份同时考虑数据库、被引用资产及必要内容版本，恢复时验证这些关系。

## 7. 执行模式与原子边界

| 模式 | 用途 | runtime 的保证 |
| --- | --- | --- |
| `stateless` | 纯计算、只读查询、帮助等 | 处理器不改变持久业务状态；消费标记与回复提交仍受统一管理 |
| `atomic` | 资产、角色、活动状态变化 | 单个数据库事务域内提交业务变化、消费标记、回复/outbox 和新任务 |
| `background`（任务类型） | 渲染、文件处理或耗时外部操作 | 持久任务协调外部阶段及短事务提交阶段 |

同步命令和事件只声明 `stateless` 或 `atomic`；`background` 属于 TaskSpec 的执行形式。接受异步工作时，命令通过 outcome 创建持久任务，不把完整外部操作包进命令事务。

原子命令的过程：开启 UoW → 检查/认领消费键 → 绑定仓储 → 执行业务 → 保存 outcome 与任务 → 提交。异常或回复入队失败时整体回滚。

消费键至少包含插件、handler 和稳定事件身份；部署升级不自动重放旧事件。回复键和任务键具有唯一约束，业务资产操作另声明自己的幂等键。

第一版使用 durable inbox 与 `handler_runs`：摄取提交后按稳定事件身份调度，崩溃恢复时继续尚未完成的 handler。无状态处理器可能重算，稳定键防止重复提交回复。此保证不覆盖 C++ 未观察、未写入或源日志已丢失的事件。

原子处理器只执行内存规则、受控数据库读写和意图构造。配置预加载，渲染、文件复制、网络及原生 IO 放在写事务之外。

跨数据库、数据库与文件、数据库与外部系统没有统一原子保证；用任务、状态与补偿表达多步过程。必要的一致性设计由对应插件声明，平台提供执行机制。

## 8. 后台任务、定时与恢复

任务类型提供 `prepare/work/commit/recover` 中实际需要的阶段：短事务受理输入，事务外工作，保存可恢复结果，再以新 UoW 提交业务变化和回复。

提交阶段发生重试时可以复用已保存结果；外部工作是否可重做必须单独声明。任务类型定义输入/结果格式版本、幂等身份、并发键、超时和恢复策略。带副作用的 work 在调用前持久标记开始；崩溃后缺少结果时先核验，不把该阶段直接恢复为可重试。

重试策略区分确定失败、可重试故障、永久拒绝和结果不确定。带副作用的外部调用结果不确定时进入待核验状态，不自动重放；插件提供查询、人工处理或补偿入口。

定时任务使用稳定计划 ID 和时间槽生成去重键。停机期间遗漏时隙的补跑、跳过或合并策略显式声明；业务截止时间持久保存，恢复时重新判断。

runtime 管理合作式取消、工作器健康与停机预算。超时不能假装线程或原生动作已结束；尚未完成工作保存为可恢复状态并报告具体停机结果。

## 9. 版本、错误与首版实现约束

公开 API 首版标记为开发期 `0.x`，稳定前允许调整并提供明确迁移说明；插件 manifest 声明兼容范围，启动检查不兼容版本。

错误分为业务拒绝、配置/装配错误、资源缺失或未就绪、基础设施失败和结果不确定。可预期业务拒绝用 outcome 返回；异常保留错误码与关联调用 ID，不泄漏数据库或原生细节到用户回复。

C++ wire v1 / JSONL schema 2 由第一版原生适配实现，协议版本独立于插件 API。旧原生会话请求保持绑定，不能改绑到新会话继续执行；迟到旧会话状态不能覆盖当前连接快照。

wire `origin` 继续使用 `manual/ai/game`。插件 ID 另行持久化；业务插件（含工具）映射为现有兼容类别 `game`，人工 API 为 `manual`，`ai` 仅解析历史，不发送未经协议支持的 `origin=plugin`。

新公共 API 和新存储表可重新设计。实现首版先固定公共模型、注册与事务契约，再用帮助、计算器和有状态计数样板验证；无需为未来能力创建空实现。

契约检查覆盖重复调用、回滚、状态质量、规则版本、资源引用、未知结果和恢复。本规格约束后续实现；现有 PluginContext、插件继承、线程与 TEMP 逻辑均可替换。部署迁移单独保持外部协议和历史数据含义。
